# Продажа VPN-подписок

Лёгкое Laravel-приложение для продажи VPN-подписок через сайт и Telegram. Веб-сайт устанавливается отдельно от серверов 3x-ui и обращается к ним через HTTPS API.

## Возможности

- Регистрация пользователей, личный кабинет и ручное назначение панели администратором.
- Настраиваемые тарифы, срок, объём трафика и ориентировочный лимит одновременных IP.
- Приём платежей через ЮKassa и Telegram Stars.
- Автоматическая выдача и продление доступа на удалённых панелях 3x-ui после подтверждения платежа.
- Telegram-бот для покупки и продления подписки.
- Подготовительные настройки криптооплаты. Криптовалютные платежи выключены до выбора и интеграции провайдера.
- Админ-панель для пользователей, тарифов, платежей, серверов и платёжных настроек.

Ограничение одновременных подключений зависит от возможностей панели и сети и не является гарантией жёсткого лимита устройств.

## Требования для локальной разработки

- PHP 8.3 или новее с расширениями `bcmath`, `curl`, `fileinfo`, `mbstring`, `openssl`, `pdo_sqlite`, `sqlite3` и `xml`.
- Composer 2.
- SQLite.
- Для установщика сервера — чистый Ubuntu 24.04 LTS.

## Локальный запуск

```sh
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate
php artisan app:make-admin admin@example.com
php artisan serve
```

Команда создания администратора спросит его имя и пароль дважды; пароль должен содержать не менее 10 символов. Для обработки очереди в отдельном терминале запустите:

```sh
php artisan queue:work database --tries=1
```

После входа в `/admin` создайте тарифы и добавьте удалённые панели 3x-ui. Все цены, сроки, лимиты трафика и ориентировочное число подключений задаются администратором.

## Установка на чистый VPS одной командой

Для установки нужен сервер **Ubuntu 24.04 LTS** с публичным доменом. До запуска направьте DNS-записи домена на IP сервера и разрешите входящие подключения к TCP-портам **80 и 443**. Установщик работает от `root`, установит системные зависимости, склонирует репозиторий, настроит приложение, SQLite, PHP-FPM, очередь, Nginx и сертификат HTTPS, предложит ввести ключи Google reCAPTCHA v2 (secret вводится без отображения) и затем попросит создать администратора.

```sh
curl -fsSL https://raw.githubusercontent.com/AlexK1984/sitevps/alexk1984-vpn-subscriptions-site/scripts/bootstrap.sh | sudo bash
```

Запускайте команду в интерактивном терминале, например в SSH-сессии. Bootstrap и установщик читают ответы напрямую из управляющего терминала, поэтому команда с `curl | sudo bash` не перехватывает ввод. В неинтерактивной среде без управляющего терминала установка остановится с понятной ошибкой.

При повторном запуске bootstrap обновляет уже существующую чистую копию установщика только fast-forward до актуальной версии ветки. Если в каталоге установщика есть незакоммиченные изменения или локальные коммиты, скрипт остановится и не будет их перезаписывать.

Установщик проверяет ОС и домен, сверяет DNS-записи A/AAAA с публичными IP VPS, проверяет доступность TCP-портов 80 и 443 и анализирует локальный firewall. Если автоматическое определение публичного IP недоступно, он попросит ввести адреса явно. Правила локального firewall автоматически не меняются: при активной фильтрации установщик остановится и попросит разрешить нужные порты; если локальная фильтрация не обнаружена, он запросит подтверждение, что порты разрешены в firewall провайдера VPS. Скрипт отказывается молча перезаписывать посторонние данные и сообщает, если существующая конфигурация мешает установке. Он не подключается к серверам 3x-ui и не запрашивает платёжные секреты. При повторном запуске следуйте сообщению установщика: завершённую установку нельзя бездумно перезаписывать.

Вручную запускать установку на рабочем VPS без резервной копии не следует. Перед использованием проверьте содержимое bootstrap-скрипта и адаптируйте ветку/команду согласно вашей политике развёртывания.

### Обновление уже установленного сайта

Не запускайте установщик повторно для обновления: он намеренно откажется работать после маркера `/var/lib/vpnsite/.installed`. Не клонируйте репозиторий поверх `/var/www/vpnsite` и не удаляйте этот маркер.

Для установки, созданной этим проектом на Ubuntu 24.04, используйте отдельный updater одной командой из SSH-терминала:

```sh
curl -fsSL https://raw.githubusercontent.com/AlexK1984/sitevps/alexk1984-vpn-subscriptions-site/scripts/update.sh | sudo bash
```

Updater проверяет завершённую установку, маркеры владельца, `.env`, путь SQLite и PHP-FPM `vpnsite:www-data`, получает текущий commit только из настроенной ветки, переводит сайт в maintenance mode, останавливает очередь и PHP-FPM, обновляет код без перезаписи `/var/www/vpnsite/.env`, `/var/lib/vpnsite/database.sqlite`, `storage` и `vendor`, затем выполняет `composer install`, миграции, пересборку кэшей и перезапускает сервисы.

**Эта команда намеренно не создаёт резервную копию. Автоматического отката нет:** при ошибке updater пытается перезапустить PHP-FPM/worker и выключить maintenance mode, но уже обновлённый код или применённые миграции могут остаться. Используйте её только если принимаете этот риск; не прерывайте процесс. Она не меняет `APP_KEY`, платёжные credentials, Nginx или PHP-FPM pool и не предназначена для ручных или изменённых установок. После завершения проверьте сайт и состояние `php8.3-fpm` и `vpnsite-worker`.

## Настройка оплат

Учётные данные ЮKassa и Telegram Bot можно задать в `/admin`. Поля секретов при повторном открытии пустые: сохранённые значения не показываются в браузере. Они шифруются Laravel при хранении в SQLite с помощью `APP_KEY`.

### CAPTCHA и восстановление пароля

Формы входа и регистрации защищены Google reCAPTCHA v2 с флажком. Создайте ключи для типа **reCAPTCHA v2 → «Я не робот»** в Google reCAPTCHA Admin Console и добавьте домен сайта. Установщик предлагает задать site key и secret key; secret вводится скрыто и сохраняется только в серверном `.env`. При ручной установке задайте `RECAPTCHA_SITE_KEY` и `RECAPTCHA_SECRET_KEY`; `RECAPTCHA_HOSTNAME` необязателен и по умолчанию берётся из `APP_URL`. Site key отображается в браузере, secret key не передаётся клиенту. Проверка выполняется сервером у Google и сверяет hostname; Google ограничивает срок действия токена и не принимает его повторно. Для этой проверки Google получает токен и IP-адрес клиента. При отсутствии ключей CAPTCHA проверка закрыта, поэтому вход и регистрацию нужно включать только после настройки ключей.

Сброс пароля доступен по ссылке «Забыли пароль?» на странице входа. Одноразовая ссылка действует 60 минут, повторная отправка ограничена по адресу и IP. Ответ всегда одинаковый, независимо от того, зарегистрирован ли адрес. Чтобы письмо отправлялось, настройте серверный `.env`: `MAIL_MAILER=smtp`, `MAIL_HOST`, `MAIL_PORT`, `MAIL_USERNAME`, `MAIL_PASSWORD`, `MAIL_FROM_ADDRESS` и при необходимости `MAIL_SCHEME` (например, `smtps`). Не используйте `MAIL_MAILER=log` для сброса паролей: приложение не отправит письмо через log/array транспорт и не запишет ссылку сброса в лог. Установщик задаёт адрес отправителя на основе домена сертификата, но не запрашивает SMTP-реквизиты; их нужно задать отдельно в `.env` на сервере и обновить конфигурационный кэш штатной командой приложения (`php artisan config:cache`). Не передавайте секреты в браузер, Git или чат.

Если credentials не сохранены в админ-панели, приложение продолжает использовать прежние переменные сервера из `.env`. Очистка значений в админке удаляет только сохранённый override и возвращает к конфигурации `.env`. Чтобы отключить способ оплаты, выключите его переключатель в админ-панели; если вы используете `.env`, удалите соответствующую серверную настройку отдельно.

### ЮKassa

Для получения уведомлений настройте URL:

```text
https://ваш-домен.example/webhooks/yookassa
```

Приложение не доверяет уведомлению само по себе: оно запрашивает платёж у ЮKassa и сверяет ID платежа, заказ, сумму, валюту RUB и статус `succeeded`. Повторные уведомления не добавляют срок подписки или трафик повторно.

Если для магазина требуются фискальные чеки, укажите `YOOKASSA_RECEIPT_VAT_CODE` и при необходимости `YOOKASSA_TAX_SYSTEM_CODE` в серверном `.env` согласно настройкам продавца и его налоговым требованиям.

### Telegram-бот и Telegram Stars

В серверном `.env` остаются `TELEGRAM_WEBHOOK_SECRET` и имя бота `TELEGRAM_BOT_NAME`; секрет webhook нельзя задавать в браузере. Настройте вебхук на:

```text
https://ваш-домен.example/webhooks/telegram
```

Передайте Telegram тот же секрет в заголовке `X-Telegram-Bot-Api-Secret-Token`. Пользователь создаёт одноразовую ссылку привязки Telegram в личном кабинете. Бот поддерживает команды `/plans` и `/renew`.

Чтобы включить Telegram Stars:

1. Сохраните токен бота в `/admin` либо настройте `TELEGRAM_BOT_TOKEN` на сервере.
2. Разрешите Telegram Stars в настройках способов оплаты.
3. Укажите целую цену в Stars для нужного тарифа.

Счёт создаётся через Telegram Payments в валюте `XTR`. Заказ подтверждается только после проверки `pre_checkout_query` и получения `successful_payment` через защищённый webhook. Подписка выдаётся через ту же очередь, что и при оплате ЮKassa.

### Тестовые платежи и журнал

В `/admin` внутренний режим тестовых оплат по умолчанию выключен. Только администратор может его включить и вручную смоделировать заказ для пользователя с назначенной панелью. Симуляция не вызывает ЮKassa или Telegram и не списывает деньги, но создаёт реально оплаченный заказ и запускает обычную выдачу/продление на 3x-ui. Такие заказы всегда помечаются `TEST`; отключение режима блокирует новые симуляции.

Журнал платёжных событий доступен только администраторам. В нём сохраняются тип события, метод, безопасная сводка и переходы статусов; webhook payload, секреты и полные платёжные реквизиты не сохраняются.

### Подготовительные настройки криптовалюты

В `/admin` можно сохранить актив, сеть, требуемое число подтверждений, срок ожидания оплаты и внутреннюю заметку. Эти поля **не запускают криптооплату**: приложение не создаёт адрес кошелька, не проверяет транзакцию и не отмечает заказ оплаченным. Криптопровайдер и его API должны быть выбраны и интегрированы отдельно.

## Подключение панелей 3x-ui

В `/admin` добавьте HTTPS API URL панели, URL-префикс подписки, логин и пароль; inbound ID и выбор протокола не нужны. При проверке соединения и каждой выдаче сайт автоматически запрашивает список inbound и находит все включённые VLESS, VMess, Trojan и Shadowsocks. Остальные протоколы пропускаются и не заявляются как подключённые. Создание клиента использует один `subId` и передаёт все найденные ID в API 3x-ui, поэтому штатный endpoint подписки 3x-ui возвращает ссылки всех включённых клиентов с этим `subId` в одной подписке. Добавление/удаление inbound на панели автоматически учитывается при следующей выдаче или повторе. Для протоколов, которые его поддерживают, можно дополнительно указать flow. Это объединяет inbound одной настроенной панели; независимые серверы 3x-ui пока не объединяются, поскольку пользователь назначается на одну панель. Пароль панели шифруется при хранении. Сайт вызывает API панели только со своего сервера; учётные данные не отправляются в браузер. Адрес панели нельзя менять после появления подписок — сначала перенесите клиентов отдельно.

В поле HTTPS URL указывайте адрес панели вместе с её настроенным base path, если он задан. Этот префикс сохраняется при запросах: сайт добавляет к нему `/csrf-token`, `/login` и `/panel/api/inbounds/list`; секретный путь не показывается в диагностике. Для проверки используйте кнопку «Проверить подключение»: сайт сначала получает сессионную cookie и CSRF-токен, затем выполняет form POST входа с `X-CSRF-Token` и read-only GET списка inbound; настройки панели и клиенты не меняются. Тот же CSRF-токен используется для защищённого POST при выдаче клиента. Для 3x-ui 3.8.5 ожидается JSON с `success: true` и `obj` CSRF-токеном, затем JSON с `success: true` при успешном входе и API-ответ со списком inbound. Перенаправления не проходят автоматически, чтобы HTML-страница входа или ошибочный base path не выглядели как результат успешного входа. Результат, время проверки, HTTP-статус и безопасная категория ошибки сохраняются в админ-панели; автоматического опроса нет. HTTP 401/403 API означает проблему сессии/доступа API и сам по себе не доказывает неверный пароль; `success: false` при HTTP 200 означает, что login endpoint не принял вход (в том числе возможны 2FA или ограничение входа). HTTP-коды 404/405, редиректы и HTML-ответы отделяются от ошибок входа. Тексты ошибок фиксированные, не показывают credentials, cookies, сырые ответы или URL-пути. Не отключайте проверку TLS для исправления ошибки сертификата.

Панель каждому пользователю назначается администратором. Оплаченный заказ без назначенной панели ждёт в статусе `paid_unassigned`; после назначения выдача ставится в очередь. Ошибки API видны администратору и допускают повторную обработку.

API и inbound-настройки могут различаться между версиями 3x-ui. До приёма платежей проверьте версию панели и конфигурацию inbound.

## Управление сайтом и поисковая оптимизация

В `/admin` есть навигация по настройкам, тарифам, панелям, пользователям, заказам и журналам. В карточке пользователя администратор может обновить имя, email, статус входа на сайт, роль, назначенную панель и параметры существующей подписки. Изменения срока, трафика и лимита подключений активной подписки отправляются на 3x-ui; пароль пользователя и секреты интеграций в карточке недоступны. Отключение аккаунта блокирует вход в сайт, но само по себе не отзывает ранее выданную конфигурацию VPN. Снять права или отключить последнего активного администратора нельзя. Критичные изменения профиля, подписки и главной страницы записываются в журнал аудита.

В разделе «Главная страница» редактируются тексты секций, CTA, название сайта, SEO title/description, canonical и HTTPS-изображение для Open Graph. Поля принимают обычный текст, не HTML/JavaScript. Сайт публикует `/robots.txt`, `/sitemap.xml`, canonical, Open Graph/Twitter metadata и базовую разметку `WebSite` с реальным названием и описанием страницы. Эти меры помогают корректно индексировать сайт, но не гарантируют первое место: ранжирование зависит от индексации, конкурентов, качества сайта и внешних сигналов. Для production задайте публичный HTTPS-домен в `APP_URL`; при необходимости уточните название бренда и SEO-тексты в админке.

## Защита и резервные копии

- Не отправляйте credentials в чат и не сохраняйте их в Git.
- Файл `.env` и SQLite-база исключены из Git; реальные ключи указывайте только на сервере или в защищённой админ-панели.
- Храните `APP_KEY` отдельно и делайте резервные копии вместе с `/var/lib/vpnsite/database.sqlite`: без исходного ключа нельзя расшифровать учётные данные панелей и платёжных сервисов.
- После изменения или восстановления `APP_KEY` сохранённые зашифрованные credentials потребуют повторного ввода.
